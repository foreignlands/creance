输入：路线纠正对话（用户七点指示）+ Claude Cage 实机点击调研

## 〇、路线纠正的定性

0.7-0.8 前半的自底向上开发把内部架构裸露成了界面——产品是"代理
管理器"的形状。纠正：**creance = agent 的安全工作台**。用户买的
是一个能放心让 AI agent 干活的地方；网络/指纹/审批/凭证全部
隐身成地基（这恰是相对竞品的差异化优势，一行不删）。

## 一、竞品印证（联网核实，2026-11-27）

| 产品 | 星数 | 印证点 |
|---|---|---|
| BloopAI/vibe-kanban | 28.8k | 多 coding agent（Claude Code/Codex/任意）统一编排是已被验证的强需求 |

结论：「多 agent 统一接入 + 安全隔离 + 账号/网络管理」三者的交集
是空位——vibe-kanban 类无隔离无网络层，Claude-Cage 只服务 Claude
一家。**creance 的卡位：多 agent 统一接入 + 唯一带安全地基的**。

## 二、信息架构

### 2.1 第一屏：三步向导（过完即隐，设置里可重开）

```
① 存储与账户  →  ② 网络代理  →  ③ 安装与检查
```

- 每步一屏，进度指示器常驻顶部；中断重开续走（已有 provision
  重放守卫地基）。
- 第②步规格见 §三。
- 第③步=现有 escape/check 探针的可视化：逐项打勾动画+失败项
  展开（期望值/实际值）+修复建议链接——复用现有证据链。
- 向导全过的状态=底部盾牌（绿=就绪/黄=降级/红=断网），
  之后**网络层永不出现在主界面**。

### 2.2 主界面：左侧空间导航 + 工作台

```
┌──────────┬────────────────────────────┐
│ 项目      │                            │
│  ＋添加   │                            │
│ 终端      │        工作台区             │
│ 浏览器    │   （终端/网页/编辑器/        │
│ Claude   │        agent 画面）          │
│ Codex    │                            │
│ Kiro     │                            │
│ Antigrav │                            │
│ …        │                            │
│ 下载      │                            │
│ ─────    │                            │
│ 设置  🛡  │                            │
└──────────┴────────────────────────────┘
```

- 左侧=空间（去哪），不是状态（是什么）——状态收敛到底部盾牌
  和操作日志。
- 关闭语义分层表照抄竞品验证过的模型：关窗≠停任务/锁定≠停/
  退出可选保留/停止才结束。

## 三、节点接入：Clash Verge 级体验（用户硬指标）

现状耻辱：一个表单+一行红字死路。目标：**粘贴订阅链接→回车→
节点列表出现→点一个→完**。规格：

1. **三导入卡并列**：订阅链接 / 拖入YAML或粘贴分享链接 / 手动节点
   ——手动节点藏进第三张卡，主路径用户永远不见 socks5 参数。
2. **鸡生蛋显式解**：首次无代理时，订阅下载提供"通过主机网络下载"
   勾选（默认推荐勾选，附一句诚实说明：仅用于订阅获取，环境不会
   因此直连）。这**不破坏 fail-closed**——主机下载的是订阅文本，
   不是环境流量；竞品已验证此交互诚实可行。
3. **自动检测本机已有配置**：扫描常见 Clash/Mihomo/Verge 配置
   目录（`~/.config/clash*`、`~/.config/mihomo`、`~/.config/verge*`），
   发现即提示"检测到本机已有 N 个订阅，一键导入"——迁移成本归零。
4. **节点列表**：卡片式（名称/类型/延迟），点选即应用；延迟测速
   经主机显式触发。分组/链式代理为高级折叠区，默认隐藏。
5. **订阅自动更新间隔**下拉（每天默认）；更新移除在用节点时保留
   原配置+显式错误（竞品纪律照抄）。
6. 失败处理：每条错误给**下一步动作**（重试/换主机下载/检查链接
   格式），永不只给一行红字。

## 四、Agent 接入点架构（核心技术设计）

用户点名清单：浏览器、终端、下载、Claude Desktop/Code、
antigravity cli/desktop、codex cli/desktop、grok、kiro cli、cursor 等。

**关键架构洞察**：我们的 agent 跑在 guest Linux 里——CLI agent
的接入=终端+启动命令，Desktop agent=guest 图形栈+启动入口。
Xvnc 浏览器通道已验证此路可行。**接入点不是逐个适配的工程，
是一套声明式注册表**：

```json
{
  "id": "claude-code",
  "name": "Claude Code",
  "type": "cli",            // cli | desktop | web
  "install": "npm i -g @anthropic-ai/claude-code",
  "launch": "claude",
  "icon": "claude.svg",
  "auth": "oauth-browser",  // 授权走内置浏览器通道（已有！）
  "quota_probe": "claude-quota",  // 可选：额度探针
  "builtin": true
}
```

- **type=cli**：在终端页签启动命令（标签带账号编号——多账号
  调度地基已有）。
- **type=desktop**：guest 内 GUI 应用，经 Xvnc 通道投到工作台
  页签（浏览器通道已验证，泛化为"应用通道"）。Linux 版缺失的
  agent（如只有 Mac/Win 的）诚实标注不可用。
- **type=web**：纯网页 agent 直接内置浏览器页签。
- **install 腿**：进 provision 的可选组件层——用户在设置里勾选
  安装哪些 agent，按需下载（镜像测速选择逻辑复用）。
- **自定义接入点**：用户可填表注册自己的 agent（名称+类型+启动
  命令）——接入点本身也是产品功能。
- 首期内置注册表：claude-code/cli、claude-desktop、codex-cli、
  kiro-cli、antigravity-cli、cursor-agent、grok(web)、terminal、
  browser——其余社区贡献。

## 六、界面打磨原则（章程第 6 条落地）

1. **实在主义**：每屏回答"用户现在要做什么"——装饰为零，
   状态/动作/进度为三要素。
2. **一屏一事**：向导每步一屏；主界面任何时刻只有一个焦点区。
3. **文案即引导**：placeholder 给例子（"例如：日常代理"），
   错误给下一步，勾选给解释——不写手册式长段。
4. **诚实降级**：任何功能不可用时给原因+替代路径，永不消失
   永不装死。
5. 参考系：Cage 的向导交互 + Clash Verge 的节点卡片 +
   vibe-kanban 的多 agent 编排心智。

## 七、明确不做（防 scope 蔓延）

- 不做插件市场（0.9+ 再议；先把内置注册表做扎实）
- 不做手机端/中继（竞品有，我们不追）
- 不做云部署（单机定位不变）
- 不动 CLI——全部新能力在 GUI 层，CLI 是地基也是退路
