# creance 威胁模型（v1，2026-11-27）

本文档明确 creance 防谁、不防谁。所有安全功能的存在意义都可以追溯到
这里列出的对手；文档之外的功能投入是错配，文档之内的缺口是立项依据。

## 对手分类

### A 类：guest 内的恶意代码（已闭环，持续维护）

**是谁**：供应链投毒（恶意 npm/pip 包）、被钓鱼的 agent、被劫持的
MCP 服务、prompt-injection 驱动下的失控 agent。它运行在 guest 里，
目标是**偷宿主的东西**或**逃出囚笼**。

**它做什么**：
1. 直接外联（绕过代理报信/外传数据）
2. 枚举环境判断自己是否身处囚笼（虚拟机指纹、硬件指纹、宿主通道）
3. 读宿主凭证（代理凭证、API key、云凭证）
4. 利用宿主侧攻击面（转发端口、控制通道、虚拟化设备漏洞）
5. 持久化潜伏

**有效防御（creance 现状）**：

| 手段 | 状态 |
|---|---|
| 单出口强制（slirp restrict + egress-lock 双层 fail-closed） | ✅ |
| 虚拟机/硬件指纹洗白（SMBIOS/ATA/MAC/DMI 种子化 OEM） | ✅ QEMU 侧；macOS vz 为 Apple 统一指纹（边界，见下） |
| 宿主通信通道隐蔽化（vsock 控制/数据面，无常驻 ssh -R 进程） | ✅ |
| 凭证不进 guest（session token 可吊销，宿主代理凭证经 keychain 隔离） | ✅ v0.7.25 起 |
| 控制面收紧（guest 桥上仅 status+plugin，开闸动作 unix-only） | ✅ |
| 敏感操作手机审批（identity-reset/persona-use/插件） | ✅ |
| 出口证据交叉验证（双源 corroborate，洗衣证据=分歧定罪） | ✅ |
| 属主绑定 + 权限巡检 | ✅ |

**A 类的意义要明确**：指纹洗白**不是**为了让 guest 里的工作负载骗过
外部平台——它是为了让恶意软件**无法发现自己身处囚笼**，从而无法针对
囚笼边界做特异性逃逸（反逃逸纵深）。这是囚笼的不可观测性。

### B 类：平台方反自动化检测（立项中，见 ROADMAP 0.8 轨）

**是谁**：Cloudflare、Google、X、各大网站的反爬/反机器人风控。它从
**网络另一端**看 guest 发出的流量，判断"这是不是真人"。

**它看什么**（按权重排）：
1. IP 信誉（数据中心/住宅、历史行为）
2. TLS ClientHello 指纹（JA3/JA4——库级指纹，curl/python/node 各不同）
3. 浏览器指纹（UA、sec-ch-ua、WebGL/Canvas/字体/屏幕、navigator 属性）
4. 行为时序（请求间隔、鼠标/键盘动力学、会话深度）
5. Cookie/账户历史一致性

**关键事实**：
- **没有任何平台风控能读到 DMI/SMBIOS/machine-id**——浏览器和 TLS
  栈都不暴露它们。A 类的洗白手段对 B 类**完全无效**，反之亦然。
- B 类防御的主要变量**不在 VM 层**：住宅代理质量 > TLS 指纹 >
  浏览器指纹 > 行为拟人。creance 能做的是 2/3/4 的工程化，
  1 永远依赖用户自己的代理质量。
- 四元组探针（国别↔时区↔语言↔locale）和 CfT 浏览器只是 B 类防御的
  最浅表皮——一致性不等于不可检测。

**0.8 立项方向**（详见 ROADMAP）：TLS 指纹拟真（uTLS/BoringSSL 定制
构建）、浏览器指纹注入（CfT 启动参数+补丁级指纹面）、行为层拟人
（请求节流/会话模式）。每一项都是独立大工程，按序立项。

### 明确不防的（边界声明）

| 项 | 理由 |
|---|---|
| 宿主本身被入侵（以用户 uid 运行的恶意进程） | keychain 抬高凭证门槛，但宿主沦陷=游戏结束，这是所有本地工具的共界 |
| guest 内核 0day → hypervisor 逃逸 | 依赖 KVM/vz 自身安全；攻击面收敛（无多余设备）是缓解不是免疫 |
| 侧信道（Spectre 类、时序） | 数据中心级威胁模型，超出个人工具范畴 |
| 流量分析去匿名化（入口-出口关联） | 需要 Tor 级网络层混入，与单出口身份一致性目标冲突 |
| macOS vz 的 SMBIOS 洗白 | Apple 不暴露注入面（lima#932 边界）；vz 指纹是"所有 Mac VM 用户"的统一指纹而非 creance 指纹，批量不可关联 |

## 功能投入的检验规则

任何安全功能在立项前必须回答：它防的是 A 类还是 B 类的哪一条具体
攻击路径？答不上来的不做。历史上"防探测"一词混用两类对手导致的
投入错配，本文档生效后不允许再发生。
