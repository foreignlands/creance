# 竞品易用性调研：Claude Cage 的用户体验设计

调研对象：`github.com/Lee-xeo/Claude-Cage`（commit 35a67e18，2026-11）。
方法：逐项通读 README、docs/guide/ 全 16 份指南、troubleshooting、agent.md、
desktop/ 与 ui/ 源码结构。本文是 0.9 桌面化筹备的输入文档——中期路线有
桌面化考虑（章程第 6 条：界面实在主义、用户使用方便）。

## 一、逐项行为观察

### 1. 获取与安装——零前置依赖

- 三平台原生安装包（dmg/exe/deb）随附一切：代理核心（Mihomo）、工作台、
  CLI。用户不需要先装 Go/Node/Docker/Clash。
- README 的快速开始是**"把这句话发给你的 agent"**——第一行就给出可原样
  粘贴给任何 AI agent 的配置指令，安装姿势本身就是 agent-first。
- 签名/公证状态逐版本在 Release 说明交代；未签名预览版明确标注"不能自动
  更新"——诚实标记取代沉默。

### 2. 首次配置——向导式分步 + 可中断续跑

- 首次打开：注册本地账户（密码+恢复密钥）→ 选存储位置 → 配代理 → 启动
  环境，**中断后重开可继续**。
- 首次下载前**实测镜像速度**（南大/中科大/官方，每个最多 5 秒或 4MiB），
  结果列出供用户选，且"经所选代理测量，不会改为直连"——测速不破坏
  fail-closed。
- 下载/安装全程组件级进度（字节数、百分比、组件名）；失败可"继续安装"
  断点续传；双边（官方源/备用源）各自保存进度。
- 存储位置可后期迁移，流程是停止→复制→校验→切换→确认后清理旧备份。

### 3. 日常使用——一个工作台收编一切

- 终端/浏览器/编辑器/Claude Desktop/插件市场同窗口。"新建 Claude 终端"
  一键起 `claude`。
- 状态可视化：绿色带钩盾牌=就绪；**检查失败时外网关闭但终端/文件仍可用**
  ——降级而非瘫痪。底部状态可点开看具体失败项；检查中可取消。
- 项目模型：一个项目可绑定多个本机文件夹（前后端同项目）；共享边界写明
  "修改直接影响本机原文件"。
- 多账号调度：额度查询、自动分配、"加入调度"复用现有登录；切账号需明确
  授权。
- `cage run` CLI 桥：在本机项目目录直接执行，自动映射进环境对应路径；
  `--here` 未共享时先询问再共享——主目录/凭据目录照常被拒。
- 关闭逻辑分层明确：关窗≠停任务，锁定≠停任务，退出可选保留环境，
  停止环境才结束终端——每张行为在文档里有对照表。

### 4. 剪贴板与附件——隐私工程学

- 双向共享剪贴板（本机/浏览器/Desktop）：文字 2MB、图片 20MB、文件
  2GB；**粘贴时才读取本机文件，同次复制只传一次**。
- 附件元数据清理矩阵：JPEG/PNG/OOXML/PDF/HEIC/MP4 等十类格式逐类定义
  "自动清理范围"与"保持可用性的处理"——GPS、时区偏移、地区代码默认
  清理，**无法安全清理时由用户选择是否原样传递**，不回退不沉默。
- 清理在主机侧完成，不经外部服务。

### 5. 错误与恢复——文档最大比重所在

- **每条故障排查以"不要做什么"收尾**："不要清空个人数据目录""不要重建
  账户""不要关闭 Gatekeeper 掩盖问题"——防止用户慌乱中自我破坏。
- **恢复入口优先于删除**："删除配置会丢失诊断线索，不作为常规排障步骤"。
- 缓存清理四段式：只读盘点→勾选确认→私有恢复批次→可撤销；恢复副本
  "原位置已有新文件时不覆盖"。
- OOM/137：引导看 OOM 计数器而非猜——"单凭退出码不能判断"。
- 忘记密码：恢复密钥路径；无解时**诚实说"当前无法恢复"**并告诉你保留什么。
- 重试机制全文档化：60 秒无新数据重试、1KiB/s 低速检测、APT 版本 bug
  （3.0.3 内存泄漏）主动升级规避。

### 6. Agent-first 接口——比我们做得彻底的部分

- `cage agent capabilities` 自描述协议（版本/操作清单/输入字段/退出码），
  **升级后先重新探测，不靠版本字符串推断**。
- 一切 agent 命令输出 JSON；密码只走 `--input` 私有文件/stdin，
  **命令行参数不接受密码**。
- 每个命令的"不做什么"写死：doctor 只读不改、init 幂等只补缺、
  service.start 复用现有后台拒绝替换不匹配构建。
- 官网 `/agent.md`、`/llms.txt`、`/llms-full.txt` 机器可读入口。
- 权力边界明示："不能替用户接受许可证、降低出口规则、授权未指定的
  主机目录"。
- 沙箱适配诚实：受限沙箱里 host.inspect 可能误报——"不要据此触发重建"。

### 7. 桌面应用使用逻辑（本轮重点）

- **单一环境多项目**：所有项目共用一个 Debian 环境/工具/账户——简化
  心智模型，但文档明示"项目之间没有独立隔离"。
- **侧栏=空间导航**：项目/浏览器/Claude Desktop/下载/设置；终端图标
  区分 Claude 终端（Agent 图标+账号编号）与普通终端。
- **画面自适应与性能**：无人操作自动降刷新率、操作即恢复 60Hz；
  "优先流畅"降绘图像素密度保控件逻辑大小；Linux 上主动关闭 Desktop
  动效（动画期间每帧重绘整块消息区）。
- **会话准备容错**：共享会话先显示"正在准备"，超 8 秒自动显示终端——
  "避免卡住的提示被隐藏"。
- **主机信任登录**："记住我"+Touch ID 绑系统钥匙串；迁移配置目录后
  凭据失效但保留密码入口——降级路径永远存在。
- **更新三分法**：应用更新/环境组件更新/Claude Desktop 更新分别管理，
  各自入口与影响写清。
- **委派窗口**（本地预览）：Claude 可通过 MCP 委派给本机 Codex——插件
  化的"出笼能力"思路的极致。

## 二、提炼出的易用性设计原则

| 原则 | 体现 |
|---|---|
| 零依赖开箱 | 安装包随附一切，用户只需"一个靠谱的代理节点" |
| 可中断可续跑 | 安装/下载/配置全链路断点续跑，双边各自存进度 |
| 降级不瘫痪 | 检查失败=外网关但本地可用；镜像不可达=跳过换源；钥匙串不可用=密码入口保留 |
| 恢复优先于删除 | 一切故障先给恢复路径，明确禁止破坏式排障 |
| 诚实边界 | 不能救的明说不行；证据不足明说不知道；不承诺过风控 |
| 防呆防慌乱 | 每条排障写"不要做什么"；危险操作要授权/确认 |
| 状态永远可见 | 盾牌/进度/具体失败项/操作详情日志，用户从不需猜 |
| 关闭语义分层 | 关窗/锁定/退出/停止各是什么，一张表说清 |
| 隐私默认清理 | 元数据能清则清，不能清则问，绝不沉默放行 |
| Agent 是一等公民 | 自描述协议+JSON+机器可读入口+明确权力边界 |

## 三、creance 差距与启示（0.9 桌面化输入）

### 差距（按优先级）

1. **"防慌乱"护栏缺失**——我们的故障文档没有"不要做什么"；用户遇到
   坏境大概率删东西自救，可能毁掉证据和数据。0.9 排查文档必须每条
   带禁止项。
2. **断点续跑标准不一**——provision 重放守卫 0.7.24 才补；他们全链路
   （下载/安装/配置）都是续跑标准。
3. **agent 协议化**——我们是 CLI 给人用，他们是协议给 agent 用
   （capabilities 自描述+JSON+stdin 秘密）。桌面化时这是底座差异。
4. **关闭语义未分层**——我们 stop/up 是硬核语义，没有"关窗保留任务"
   的中间态概念（桌面化时才真正需要）。
5. **附件/剪贴板隐私工程**——完全空白（我们还没有桌面 shell，属未来项）。
6. **状态可视化的降级设计**——我们的 check 是 CLI 一次性输出；他们的
   盾牌+具体失败项+可取消是持续状态面。

### 我们保持的优势（不抄）

- 审计纪律/变异测试/fail-closed 证据链——他们的"11 项关键检查"思路
  与 escape 探针同源但更浅。
- 威胁模型文档化（THREAT-MODEL.md A/B 类分离）——他们没有等价的
  对手分层。
- Rust 单二进制+两平台收窄的维护面——他们 Go 全栈 50+ 包含 mobile/
  relay/desktop，维护面巨大。

### 0.9 可执行项建议

1. 排查文档改造：每条故障补"不要做什么"+恢复入口优先（纯文档工作）。
2. CLI 输出双模：`--json` 全局旗标+`capabilities` 自描述命令（桌面化
   底座，也为 agent 协作铺路）。
3. 桌面 shell 设计稿时引入"关闭语义分层表"与状态盾牌模型。
4. 密钥环/记住我已有 keychain 地基（0.7.25），桌面化时顺势接生物识别。
